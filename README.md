# Образовательная платформа: бот + сайт

Платформа для школьников 10–13 лет. Не понял тему на уроке? Напиши её или
сфоткай задание, и Gemini объяснит тему по шагам. После каждого шага идёт
мини-проверка, за верные ответы начисляются очки, уровни и серии дней.
Родители получают отчёты, учителя видят статистику ошибок класса.

Telegram-бот и сайт работают как **одна система**:

- **Один пользователь — одна запись в БД**, откуда бы он ни зашёл: бот,
  Telegram Login Widget, Mini App или логин с кодом без Telegram.
- **Общие очки, темы и серии.** Лимит 20 объяснений в день тоже общий.
- **Тему можно начать в боте и продолжить на сайте** (или наоборот) с того же шага.
- **Родитель и учитель получают сообщение в боте**, когда ученик закрыл тему.
- **Поддержка** — у родителя и учителя в боте (кнопка «💬 Поддержка», `/support`):
  вопрос (можно со скриншотом) уходит владельцу (`OWNER_ID`) с кнопкой
  «✉️ Ответить», ответ приходит автору в бот на его языке. Обращения хранятся
  в `support_tickets`; владельцу `/support` показывает открытые. Не больше
  5 обращений в сутки от одного человека.
- **Журнал результатов** — у родителя и учителя: в боте (`/journal`, кнопка
  «📒 Журнал») и на сайте (`/journal`, родитель и учитель попадают туда сразу
  после входа). По каждой закрытой теме: когда, сколько вопросов верно
  с первой попытки, сколько ошибок и очков; по ученику — темы за неделю,
  точность и трудные темы.
- **В боте у каждого шага есть кнопка «🌐 Открыть на сайте»**: она открывает
  ту же тему в Mini App.

## Устройство

```
.env                  один файл настроек на все сервисы
docker-compose.yml    postgres + backend + bot + web
backend/              FastAPI и ОБЩЕЕ ЯДРО (пакет `app`) — его используют и API, и бот
  app/core/           настройки, время, переводы, JWT, проверка подписей Telegram
  app/db/             модели SQLAlchemy (async), подключение
  app/repositories/   запросы к БД
  app/services/       explain (сценарий «Не понял тему»), gemini, accounts, gamification
  app/api/            роутеры /api/...
  app/locales/ru.json тексты бота
  alembic/            миграции
  scripts/            перенос из SQLite, демо-ученик
bot/                  aiogram 3 — только Telegram-интерфейс поверх общего ядра
web/                  Next.js 14 (App Router, TypeScript, Tailwind)
  messages/ru.json    все тексты сайта
```

Как части связаны между собой:

- **Состояние объяснения хранится в БД** (`topics.steps`, `current_step`), а не
  в памяти бота. Кнопки бота содержат номер шага: если ученик уже ответил на
  сайте, старая кнопка не засчитается, и бот покажет актуальный шаг.
- **Уведомления идут через очередь событий** (таблица `events`). Когда тема
  закрыта, сервис кладёт в очередь событие. Бот раз в 5 секунд забирает события
  и пишет родителям. В PostgreSQL используется `FOR UPDATE SKIP LOCKED`,
  поэтому при нескольких экземплярах бота сообщения не задвоятся.
- **Лимит резервируется атомарным upsert**, поэтому одновременные запросы из
  бота и с сайта не превысят 20 в день. Если модель не ответила, попытка
  возвращается.
- **Фото задания** живёт только в памяти запроса: оно уходит в Gemini и нигде
  не сохраняется. Сайт перед отправкой уменьшает фото до 1600 px.

## Качество объяснений

Ребёнок не должен выучить ошибку модели. Поэтому каждое объяснение и каждая
задача для закрепления проходят проверку, прежде чем их увидит ученик:

1. **Арифметика проверяется кодом без ИИ** (`backend/app/services/checks.py`):
   если в вопросе есть пример («12 × 3», «1/2 + 1/4»), программа сама считает
   ответ точными дробями и сверяет с отмеченным вариантом.
2. **Второй, независимый запрос к модели** — «проверяющий учитель» с отдельной
   инструкцией и температурой 0 — решает каждый вопрос заново.
3. Не прошло проверку — объяснение генерируется заново. Не прошло дважды —
   ученик видит честное «не получилось», попытка из лимита возвращается.
4. **Кнопка «⚠️ Здесь ошибка»** у каждого шага и задачи (сайт и бот).
   Жалоба сразу приходит владельцу и учителю ученика в Telegram, список —
   `/reports`, кнопка «✅ Разобрано».

**Очки:** 10 — за верный ответ с первой попытки, 5 — со второй, дальше 0.
Перебором вариантов очки не набрать.

**Лимиты расходов на Gemini:** 20 объяснений в день, «Объясни проще» — не
больше 3 раз на шаг и 60 в день, задачи для закрепления генерируются один раз
на тему.

## Вход по номеру телефона и семейный аккаунт (Модуль 4, п. 2.1)

- **SMS-вход** (`/login` → «Вход по номеру телефона»): +998 и 9 цифр → код из 6 цифр,
  5 минут, не больше 5 попыток; повторная отправка — через минуту, не больше 5 SMS в
  час на номер. В БД — HMAC кода. Шлюз — Eskiz.uz (`SMS_PROVIDER=eskiz`) или лог
  сервера для разработки. Новый номер — новый пользователь: роль, имя и класс на `/welcome`.
- **Семья** (`/family`): многие ко многим — все взрослые семьи видят всех её детей
  (до 4 взрослых и 6 детей). Приглашение — 6 цифр или QR (24 часа, одноразово); взрослый
  вступает только после подтверждения номера по SMS. Семья поддерживает `parent_links`,
  на которых работают журнал, отчёты и бот.
- Доступ к данным детей проверяется в API и покрыт тестами безопасности. Row Level
  Security в PostgreSQL — следующий шаг (см. ответ на раздел 8 ТЗ).

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/v1/auth/sms/request` | `{phone, lang}` → SMS с кодом |
| POST | `/api/v1/auth/sms/verify` | `{phone, code}` → `{token, me}` |
| POST | `/api/v1/me/role` | Первый вход: `{role: student\|parent, name, grade?}` |
| GET | `/api/v1/family` | Состав семьи и лимиты |
| POST | `/api/v1/family/invites` | Код + ссылка + QR (SVG) |
| POST | `/api/v1/family/join` | `{code}` — вступить в семью |

## Вечерний тест, Exam Readiness Score и отчёт родителю (Модуль 4)

- **Программа** — `curriculum_subjects` / `curriculum_topics` (класс, порядок, названия
  uz/ru/en). В репозитории — **образец** (`app/data/curriculum_sample.json`, грузится в
  пустой каталог при старте); официальную программу загрузить:
  `python scripts/load_curriculum.py путь.json`. Объяснения («Не понял тему») сами
  привязываются к теме программы по названию на трёх языках — без запросов к ИИ.
- **Вечерний тест** (`/evening`, 17:00–22:00 по Ташкенту): 5–7 вопросов по сегодняшним
  темам + 1–2 на повторение тем 3, 7 и 14 дней назад. Сложность адаптивная (1–3).
  Ошибка — объяснение и вторая попытка, за исправление монеты; для ERS считается только
  первая попытка. Junior (≤ 7 класс) — крупные кнопки и озвучка вопроса (синтез речи
  браузера), Senior — таймер.
- **Банк вопросов** `question_bank`: вопросы по теме и сложности генерируются ИИ один
  раз, перепроверяются вторым запросом и переиспользуются всеми учениками.
- **Серия** не сгорает: 2 бесплатные «заморозки» в неделю (`FREEZES_PER_WEEK`).
- **ERS** = 0.50·M + 0.25·S + 0.15·V + 0.10·R (`ERS_WEIGHTS`) — пересчитывается после
  каждого теста, история в `readiness_scores`; меньше 20 ответов — «Недостаточно данных»;
  рядом всегда совет «повторите темы: …».
- **Отчёт родителю** (`/family/{id}`): итог теста, ERS по предметам, светофор тем
  (80%+ / 50–79% / <50%), динамика за неделю и месяц, аккуратность работ (из проверки
  фото), «Прислать ребёнку задание», время напоминания.
- **Бот**: напоминание о тесте во время, выбранное семьёй (не чаще раза в день и только
  если тест не пройден); родителю — «Азиз сегодня понял 4 из 5 тем. Слабая тема: …»;
  ребёнку — присланное задание. Push-каналом служит Telegram (FCM — после мобильного
  приложения).

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/v1/evening` | Окно, тест за сегодня, текущий вопрос |
| POST | `/api/v1/evening/start` | Начать (или продолжить) тест |
| POST | `/api/v1/evening/{id}/answer` | `{slot, option, time_ms}` → верно/объяснение/следующий вопрос/итог |
| GET | `/api/v1/readiness?student_id=` | ERS по предметам с советом и историей |
| GET | `/api/v1/family/report?student_id=` | Отчёт родителю / учителю |
| POST / GET | `/api/v1/assignments` | Задание по теме / открытые задания ученика |
| PUT | `/api/v1/family/evening-time` | Время напоминания (17:00–22:00) |

## Панель учителя (Модуль 5, п. 4.3)

`/teacher`: тепловая карта «ученики × темы» (последние 5 ответов по теме), «Кому нужна
помощь» (точность за неделю упала на 15+ п.п. относительно предыдущей), частые вопросы
класса к ИИ (по объяснениям за 30 дней), задание всему классу или выбранным ученикам
(`POST /api/v1/teacher/assignments`), переходы к проверке работ и урокам по учебнику.

## Academic Copilot: ИИ-проверка рукописных работ (Модуль 5.1)

Учитель на сайте (`/teacher/checks`) загружает фото или PDF работ класса. ИИ
распознаёт текст и формулы, сверяет с заданием и ключом и **предлагает** оценку,
пометки ошибок с координатами на фото, комментарий ученику, аккуратность и свою
уверенность. **Оценку ставит учитель**: к ученику и родителям (в бот) она уходит
только после подтверждения.

| Уверенность ИИ | Что может учитель |
| --- | --- |
| ≥ 90% | Подтвердить в 1 клик (в том числе пачкой «Подтвердить готовые») |
| 70–89% | Жёлтая метка «Проверьте»: подтвердить можно после открытия работы |
| < 70% или сбой ИИ | Только после ручной оценки |

- **Конвейер:** проверка типа файла по содержимому → предобработка (поворот по EXIF,
  обрезка полей, контраст, ≤ 2400 px, HEIC → JPEG) → Gemini Vision (температура 0,
  строгая JSON-схема) → очередь учителя. Пороги — `CHECK_ONE_CLICK_CONFIDENCE`,
  `CHECK_REVIEW_CONFIDENCE`, меняются без релиза.
- **Очередь** — в БД (`work_check_items`): `queued → processing → review → confirmed / failed`,
  до `CHECK_MAX_ATTEMPTS` повторов, зависшие работы возвращаются в очередь.
  В PostgreSQL обработчиков может быть несколько (`FOR UPDATE SKIP LOCKED`):
  `CHECK_WORKER=0` в API и `python -m app.workers` отдельными процессами.
- **Размеченные данные:** оценка и пометки ИИ хранятся отдельно от решения учителя;
  пара «ИИ / учитель» пригодна для дообучения — только если школа дала согласие
  (`training_consent` на проверке).
- **Файлы** — в `MEDIA_DIR` под случайными именами (в Docker — том `media`, входит в
  ежедневный бэкап). Выдаются только учителю, который их загрузил.
- Без ключа Gemini (`GEMINI_FAKE=1`) работает демо-заглушка с уверенностью 95/80/55%.

Не сделано в этой версии: выравнивание перспективы (нужен OpenCV), экспорт в журнал
школы, метрики точности на наборе из 500 реальных работ (набора пока нет).

## Academic Copilot: уроки по учебнику, RAG (Модуль 5.2)

Учитель (`/teacher/materials`) выбирает учебник из библиотеки платформы или
загружает свой PDF (с обязательным основанием прав — `license_note`), вводит тему
и получает за один запрос: **план урока на 45 минут**, **Stories-урок** (8–12
слайдов, часть — с вопросом), **контрольную в 2–4 вариантах** и **ключ ответов**.
Всё редактируется; выгрузка — DOCX (сервер) и PDF (печать страницы).

- **RAG:** PDF → текст по страницам (PyMuPDF) → фрагменты ~900 символов с
  перекрытием, не пересекающие границу страницы → эмбеддинги (Gemini
  `gemini-embedding-001`, 768; без ключа — локальный хэш-эмбеддинг) → поиск
  ближайших фрагментов. В промпт идут только найденные фрагменты с номерами страниц.
- **Защита от выдумок:** нет фрагментов по теме — ответ `topic_not_in_textbook`, урок
  не генерируется; страницы-источники в ответе — только из найденных фрагментов.
  План всегда ровно на 45 минут, число вариантов — ровно запрошенное.
- **Скан без текстового слоя** — учебник получает статус `failed / no_text_layer`
  (нужен OCR — следующий шаг).
- Поиск — косинусная близость в Python (~600 фрагментов на учебник). Для PostgreSQL
  следующий шаг — колонка pgvector и индекс HNSW (меняется только `rag.retrieve`).
- Иллюстрации к слайдам — пока описание «что нарисовать», без генерации картинок.

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET / POST | `/api/v1/teacher/textbooks` | Библиотека + свои учебники / загрузка PDF (индексация в фоне) |
| GET / DELETE | `/api/v1/teacher/textbooks/{id}` | Статус учебника / удаление своего |
| POST | `/api/v1/teacher/materials` | `{textbook_id, topic, variants: 2–4, lang?}` → материалы урока |
| GET | `/api/v1/teacher/materials[/{id}]` | Список / материал |
| PUT | `/api/v1/teacher/materials/{id}` | Правка учителем (ключ ответов пересобирается) |
| GET | `/api/v1/teacher/materials/{id}/export.docx` | Выгрузка в Word |

## Безопасность сайта и API

- **Ограничение частоты по IP:** вход — 10 запросов в минуту (защита от
  перебора кодов), создание объяснений — 20, остальное — 180.
- **Отзыв сессий:** «Выйти» на сайте завершает все сессии пользователя на
  всех устройствах; новый код от родителя отключает старые входы ребёнка.
- **Заголовки безопасности:** Content-Security-Policy (скрипты только свои и
  Telegram, `eval` запрещён), `X-Content-Type-Options`, `Referrer-Policy`,
  `Permissions-Policy`, HSTS на боевом сервере.
- Вход через Telegram-виджет работает в режиме переадресации (`data-auth-url`),
  без `eval`. Подпись проверяется на сервере.
- Контейнеры запускаются не от root.

## Персональные данные

- **Журнал согласий** (`consent_records`): кто, за кого, когда и на какую
  версию политики дал согласие. Сменили текст политики — увеличьте
  `POLICY_VERSION`: родители подтвердят согласие заново.
- **Политика конфиденциальности** — страница `/privacy` на трёх языках.
  Оператор, контакты и место хранения задаются в `.env`. **Текст — шаблон,
  его должен проверить юрист** (см. [DEPLOY.md](DEPLOY.md), раздел 9).
- **Удаление данных:** родитель в боте открывает «Профиль» → «🗑 Удалить
  данные» — аккаунт, прогресс и темы ребёнка удаляются, в журнале остаётся
  только отметка об удалении.

## Безопасность бота

- Бот отвечает только в личных чатах, сообщения из групп и каналов игнорируются.
- **Анти-флуд:** при больше чем 6 действиях за 3 секунды лишние отбрасываются,
  пользователь получает мягкое предупреждение.
- **Бан-лист владельца:** `/block <id> [причина]`, `/unblock <id>`, `/status`.
  Список хранится в таблице `blocked_users` и действует **и в боте, и на
  сайте**: заблокированный не войдёт через Telegram, а его открытые сессии на
  сайте получат ошибку 403.
- Имена и названия тем экранируются в сообщениях с HTML-разметкой.
- Тема длиннее 500 символов не принимается: бот и сайт просят написать короче
  или прислать фото.

## Быстрый старт через Docker

```bash
cp .env.example .env      # заполни BOT_TOKEN, BOT_USERNAME, GEMINI_API_KEY, JWT_SECRET, POSTGRES_PASSWORD
docker compose up -d --build
```

- Сайт: http://localhost:3000
- API и документация: http://localhost:8000/docs
- Бот запускается сам. Миграции применяет контейнер `backend` при старте.

Демо-ученик, чтобы зайти на сайт без Telegram (логин `demo`, код `123456`):

```bash
docker compose exec backend python scripts/create_demo_student.py
```

Без ключа Gemini всё можно проверить на демо-объяснениях: поставь `GEMINI_FAKE=1`.

## Запуск без Docker

Нужны Python 3.11+, Node.js 20+ и PostgreSQL 14+. Для быстрой локальной
проверки подойдёт и SQLite: `DATABASE_URL=sqlite:///./education.db`.

```bash
cp .env.example .env
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -e "./backend[dev]" -r bot/requirements.txt

# 1. База
cd backend
alembic upgrade head

# 2. API (терминал 1)
uvicorn app.main:app --reload --port 8000

# 3. Бот (терминал 2)
cd bot && python main.py

# 4. Сайт (терминал 3)
cd web && npm install && npm run dev      # http://localhost:3000
```

Сайт проксирует `/api/*` на `BACKEND_INTERNAL_URL` (по умолчанию `http://localhost:8000`).

## Перенос данных со старого бота (SQLite → PostgreSQL)

```bash
cd backend
alembic upgrade head                                          # пустая схема в PostgreSQL
python scripts/migrate_sqlite_to_pg.py /path/to/education_bot.db --dry-run   # проверить
python scripts/migrate_sqlite_to_pg.py /path/to/education_bot.db             # перенести
```

Что сохраняется: пользователи (старый `id` становится `telegram_id`), роли, очки,
серии, коды семьи, согласия родителей, привязки, закрытые темы, статистика
ошибок для учителей и дневные лимиты. Незавершённые темы получают статус
`abandoned`: старый бот держал их шаги в памяти, так что продолжить их нельзя.

## Вход на сайт

| Способ | Как работает |
| --- | --- |
| Telegram Login Widget | Кнопка на `/login`. Бэкенд проверяет подпись HMAC-SHA256 с ключом `SHA256(BOT_TOKEN)` и свежесть `auth_date`. В @BotFather нужно выполнить `/setdomain` и указать домен сайта. |
| Через бота | Кнопка «Войти через Telegram-бота» на `/login` — работает на **любом адресе** (localhost, IP в сети), домен в @BotFather не нужен. Сайт показывает число и открывает `t.me/<бот>?start=login_<токен>`; в боте нужно нажать то же число из трёх (чужая ссылка на вход бесполезна: неверное число или «Это не я» отменяют запрос). Запрос живёт 5 минут и срабатывает один раз, в БД — только хэш токена. API: `POST /api/auth/bot/start`, `POST /api/auth/bot/poll` (202 — ждём, 200 — токен). |
| Mini App | Если сайт открыт из бота, вход происходит автоматически по `initData`. Подпись проверяется с ключом `HMAC("WebAppData", BOT_TOKEN)`. |
| Логин и код | Для детей без Telegram. Родитель или учитель в боте нажимает «🔑 Вход для ребёнка без Telegram» и получает логин и 6-значный код. В БД хранится только хэш кода (scrypt). После 5 ошибок вход блокируется на 15 минут. Новый код выдаётся кнопкой «🔄 Новый код». |

Кто даёт согласие на обработку данных:
- если вход создал **родитель**, согласие ставится сразу;
- если вход создал **учитель**, ученик ждёт согласия родителя: родитель
  привязывает ребёнка по коду семьи и нажимает «Обработка данных».

Mini App и кнопки «Открыть на сайте» работают только по **HTTPS**
(`WEB_URL=https://...`). Для локальной разработки подойдёт туннель, например
`cloudflared tunnel --url http://localhost:3000` или `ngrok http 3000`. Пока
`WEB_URL` не на HTTPS, бот просто не показывает эти кнопки.

## API

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/auth/telegram` | `{widget: {...}}` или `{init_data: "..."}` → `{token, me}` |
| POST | `/api/auth/code` | `{login, code}` → `{token, me}` |
| GET | `/api/me` | Профиль и настройки оформления |
| PATCH | `/api/me/settings` | `theme` (sun/ocean/forest/berry), `high_contrast`, `dyslexia_font`, `lang` |
| GET | `/api/progress` | Очки, уровень, серия, незавершённые и закрытые темы, остаток лимита |
| POST | `/api/explain` | multipart: `title`, `subject`, `grade`, `photo?` → тема с шагами |
| GET | `/api/explain/{id}` | Тема (можно продолжить с текущего шага) |
| POST | `/api/explain/{id}/answer` | `{step, option}` → верно или нет, очки, завершение |
| POST | `/api/explain/{id}/simplify` | Более простое объяснение текущего шага (вопрос тот же) |
| POST | `/api/explain/{id}/practice` | 3 задачи для закрепления закрытой темы |
| POST | `/api/explain/{id}/report` | «⚠️ Здесь ошибка»: `{step, kind: step\|practice, comment?}` |
| GET | `/api/journal` | Журнал для родителя/учителя: `student_id?`, `limit?` (до 100), `before?` (id темы — «показать ещё») → `{students, entries, has_more}` |
| POST | `/api/v1/teacher/checks` | Academic Copilot: загрузка работ (multipart `files[]` — JPG/PNG/HEIC/PDF, до 40 × 10 МБ; `title`, `subject`, `grade`, `task_text`, `answer_key`, `max_score`, `student_ids[]`, `training_consent`) → `check_id` |
| GET | `/api/v1/teacher/checks` | Проверки учителя со счётчиками по статусам |
| GET | `/api/v1/teacher/checks/{id}` | Статус и результаты; `?level=one_click\|review\|manual` — фильтр по уверенности ИИ |
| GET | `/api/v1/teacher/checks/{id}/items/{item_id}` | Открыть работу: распознанный текст, пометки, комментарий (открытие фиксируется) |
| GET | `/api/v1/teacher/checks/{id}/items/{item_id}/file` | Фото/PDF работы |
| PATCH | `/api/v1/teacher/checks/{id}/items/{item_id}` | Правка учителем: `score`, `comment`, `marks`, `student_id` |
| POST | `/api/v1/teacher/checks/{id}/confirm` | Подтверждение (`item_ids?`); 409 `confirm_blocked` + причины, если правила уверенности не выполнены |
| POST | `/api/auth/logout` | Выход на всех устройствах |
| GET | `/api/config` | Публичные настройки (имя бота для виджета) |

Все запросы, кроме входа и `/api/config`, требуют заголовок `Authorization: Bearer <token>`.
Ошибки приходят в виде `{"detail": {"code": "limit_reached"}}`, фронт переводит код в текст.
Правильные ответы на непройденные шаги клиенту не отправляются.

Формат шага от Gemini:

```json
{"title": "…", "text": "…", "example": "…",
 "visual": {"type": "number_line|fractions|table|arrows|cards", "data": {…}, "caption": "…"},
 "check_question": "…", "options": ["…", "…", "…"], "correct": 0}
```

Сайт рисует `visual` как SVG или карточки: числовую прямую, дроби-кружки,
таблицу, цепочку шагов со стрелками или карточки. В боте та же схема
показывается текстом.

## Дизайн сайта

- Экраны сначала рассчитаны на телефон. На каждом экране крупные «объёмные»
  кнопки и мало текста. Маскот — носорог (`web/public/mascot-*.webp`, исходник — `Насарог.png`);
  «думает» — с пузырьками мыслей, «радуется» — с искорками цвета темы.
- Шаг устроен так: крупный заголовок, короткий текст, пример, схема и
  прогресс-бар «Шаг 2 из 4». Внизу панель ответа: зелёная «Верно! +10 ⭐»
  или «Объясни проще».
- Финал: конфетти, итоги и кнопка «Закрепить ещё 3 задачами».
- 4 темы (Солнце, Океан, Лес, Ягоды), режим высокого контраста и шрифт для
  лёгкого чтения. Выбор сохраняется в профиле пользователя.
- Шрифт для лёгкого чтения — **Andika** (SIL): его сделали для начинающих
  читателей, и в нём есть кириллица. У OpenDyslexic кириллицы нет, для
  русского интерфейса он не подходит.
- Анимации отключаются при системной настройке «уменьшить движение».

## Переводы

Три языка: **русский, узбекский (латиница) и английский**.

- Бот: `backend/app/locales/{ru,uz,en}.json`.
- Сайт: `web/messages/{ru,uz,en}.json`.

Как выбирается язык:
- Язык хранится в профиле (`users.lang`) и **общий для бота, сайта и
  объяснений Gemini**: сменил в боте (кнопка «🌐 Язык» или `/language`), и
  сайт тоже переключится.
- Новому пользователю язык берётся из настроек его Telegram (uz → узбекский,
  en → английский, иначе русский).
- На странице входа сайта язык можно выбрать до входа.
- Рассылки родителям (уведомления, отчёты) приходят на языке родителя.

Недостающие ключи автоматически берутся из русского. Тест `backend/tests/test_i18n.py`
проверяет, что во всех языках одинаковые ключи и подстановки.

## Настройки .env

| Переменная | Описание |
| --- | --- |
| `BOT_TOKEN`, `BOT_USERNAME` | Токен и имя бота от @BotFather |
| `OWNER_ID` | Telegram ID владельца: команды `/block`, `/unblock`, `/status` (свой ID — `/myid`) |
| `FLOOD_MAX_MESSAGES`, `FLOOD_WINDOW_SECONDS` | Анти-флуд: не больше 6 действий за 3 секунды (по умолчанию) |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | Ключ Google AI Studio и модель |
| `GEMINI_FAKE` | `1` — демо-объяснения без Gemini |
| `DATABASE_URL` | `postgresql://…` (или `sqlite:///…` для локальной проверки) |
| `POSTGRES_*` | Учётка PostgreSQL для docker-compose |
| `WEB_URL` | Публичный адрес сайта (HTTPS нужен для Mini App) |
| `JWT_SECRET` | Длинная случайная строка для токенов сайта |
| `CORS_ORIGINS` | Разрешённые источники, если API вызывают напрямую |
| `MAX_PHOTO_MB` | Максимальный размер фото (по умолчанию 5) |
| `DAILY_EXPLAIN_LIMIT` | Общий лимит объяснений в день (по умолчанию 20) |
| `POINTS_PER_STEP` | Очки за верный шаг (по умолчанию 10) |
| `TIMEZONE` | Таймзона отчётов и «сегодня» (по умолчанию `Asia/Tashkent`) |
| `PRIVACY_POLICY_URL` | Ссылка на политику обработки данных |
